# UC-002 View editions

Formerly testing plan §9 Q10–Q11.

## List and visibility
- One list with every visible edition and its state. The frontend separates ongoing from published.
- Guests and participants see every announced edition (`ACTIVE`, `CLOSED`, `PUBLISHED`); `CLOSED` ones are listed
  with the ongoing ones. A participant otherwise sees the same as a guest.
- Staff (designer, facilitator, administrator) also get `PLANNED` editions in the same endpoint, even without a
  filter.
- No order is required.

Decisions: D-016, D-021, D-036.

## Filtering by state
- A guest asking for `PLANNED` editions (`?state=PLANNED`) → `401`; a participant → `403`.

Decisions: D-021.

## Item shape (exact)
- Every role: `id`, `state`, `name`, `year`, `shortDescription`, `logo`, plus optional `fruitLogo`; no other field.
  - `logo` is a link (e.g. `https://drive.google.com/thumbnail?id=…&sz=s4000`).
  - Short description and logo are compulsory only for non-planned editions; for `PLANNED` items (staff) they may be
    missing or `null`.
  - The long description appears only in the details (UC-003).
- Staff also get `driveLink` (the edition's Drive folder: logo and other edition info). Guests and participants
  never do.

Decisions: D-021, D-022, D-023.
