# UC-004 View hackathons

Formerly testing plan §9 Q15.

## List and visibility
- Endpoint `GET /hackathons`. The list has no filter.
- Guests and participants see every hackathon that is not `PLANNED` and not private: announced (`OPEN`), closed,
  ongoing (shown as incoming; they're only there for the hackathon's duration) and ended.
- Private (internal) hackathons: staff only. Staff also get `PLANNED` ones in the same endpoint.
- No order is required (the frontend sorts).

Decisions: D-028, D-029.

## Item shape (exact)
- Guests and participants: `id`, `state`, `phase`, `type`, `startDate`, `endDate`, `shortDescription`, `location`
  (online: absent or `null`), `logo` (a link), `editionName` (the edition's name), plus `isEnrolled` for
  authenticated users only.
- Staff may also get `internalName`, `isPrivate`, `driveLink`.
- `meetLink` is never in the list. No internal name, full description or Drive link for non-staff.

Decisions: D-028.

## `isEnrolled`
- `true` when the user has a participation in that hackathon (assisting or not, ended ones included), otherwise
  `false`.
- Being an evaluator doesn't count.
- Guests never get it.

Decisions: D-028.

## Moved to hackathon details
The `closest` and `active` filters each return one hackathon, so they belong with the hackathon details use case.
`incoming` and `previous` are removed from the product. Answers so far:
- `active` = the caller's hackathon (participation) that has started and not ended; a guest asking for it → `401`.
- `closest`: rules not asked yet.

Decisions: D-028, D-029.
