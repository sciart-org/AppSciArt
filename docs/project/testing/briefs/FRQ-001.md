# FRQ-001 Authentication: sessions → `backend/tests/acceptance/authentication.test.js`

## Requirement
- FRQ-001 Authentication (`srs-export.txt` ~line 3101): "The system shall authenticate registered users before
  granting access to functionalities restricted to authenticated actors."
- Use case assumptions (~line 806): "Authentication is a precondition, except for those use cases in which the
  principal actor is Guest or User."
- This brief covers sessions only: which sessions open restricted functionality, over the API and over the
  real-time connection. Login itself and guests on every restricted operation come with the rest of FRQ-001
  (plan §4, FRQ-001).

## Clarifications
- `docs/project/clarifications/general.md`: "Actors", "HTTP meaning".
- D-057: a session is valid whether the project signs it with its published keys (what the local stack does on a
  real login) or with its legacy shared secret (what the hosted projects still do). Both must be accepted.

## Vocabulary
- Session = the access token a client sends as `Authorization: Bearer <token>`.
- Restricted operation used here: `GET /me` (the caller's own profile). Only its status matters in this file; its
  content is UC-008.
- Real-time connection = `socketAs(user, { token })`: it resolves when the connection is accepted and rejects when it
  is refused.

## Test cases
- **B1** A user's session from a real login (`tokenOf`) gets `GET /me` with `200`.
- **B2** The same session opens the real-time connection.
- **B3** A user's session signed with the legacy shared secret (`legacyTokenOf`) gets `GET /me` with `200`.
- **B4** The same legacy session opens the real-time connection.
- **B5** A token signed with a key the project doesn't publish (`forgedTokens.unknownKey`) gets `GET /me` with `401`.
- **B6** The same token is refused on the real-time connection.
- **B7** An expired, a wrong-key, an unsigned and a garbage token (`forgedTokens.expired`, `wrongKey`, `unsigned`,
  `garbage`) each get `GET /me` with `401`.
- **B8** Each of those four tokens is refused on the real-time connection.
- **B9** A request with no token gets `GET /me` with `401`.

## Fixture notes
- Base users only; no other fixtures. Use a participant (no staff role), e.g. `participant(1)`.
- Each case states the actor's session explicitly; don't reuse a refused socket.
