# FRQ-001 Authentication: sessions → `backend/tests/acceptance/authentication.test.js`

> Scope (2026-11-24): which sessions open restricted functionality, over the API and over the real-time connection,
> including a connection that outlives its session. Login itself and guests on every restricted operation are tested
> when Phase 1a reaches FRQ-001; this file is extended then.

## Requirement
- FRQ-001 Authentication (`srs-export.txt` ~line 3101): "The system shall authenticate registered users before
  granting access to functionalities restricted to authenticated actors."
- Use case assumptions (~line 806): "Authentication is a precondition, except for those use cases in which the
  principal actor is Guest or User."

## Clarifications
- `docs/project/clarifications/general.md`: "Actors", "HTTP meaning".
- D-057: a session is valid whether the project signs it with its published keys (what the local stack does on a
  real login) or with its legacy shared secret (what the hosted projects still do). Both must be accepted.
- User, 2026-11-09: a session with no expiry, or one naming an algorithm the project doesn't sign with, is not valid.
- User, 2026-11-24:
  - A real-time connection is only for a registered user: a valid session whose account has no user profile (a
    deleted user, or one who never completed registration) is refused.
  - When the session expires, the open connection is told so and closed; the user signs in again, as over the API.

## Vocabulary
- Session = the access token a client sends as `Authorization: Bearer <token>`.
- Restricted operation used here: `GET /me` (the caller's own profile). Only its status matters in this file; its
  content is UC-008.
- Real-time connection = `socketAs(user, { token })`: it sends the session in the connection's `auth` payload,
  resolves when the connection is accepted and rejects when it is refused.
- Expired session on an open connection: the server sends the event `session_expired` and then closes the
  connection (the client sees `disconnect`).

## Test cases
- **B1** A user's session from a real login (`tokenOf`) gets `GET /me` with `200`.
- **B2** The same session opens the real-time connection.
- **B3** A user's session signed with the legacy shared secret (`legacyTokenOf`) gets `GET /me` with `200`.
- **B4** The same legacy session opens the real-time connection.
- **B5** A token signed with a key the project doesn't publish (`forgedTokens.unknownKey`) gets `GET /me` with `401`.
- **B6** The same token is refused on the real-time connection.
- **B7** Each of these tokens gets `GET /me` with `401`:
  - expired (`forgedTokens.expired`), wrong key (`wrongKey`), unsigned (`unsigned`), garbage (`garbage`)
  - no expiry (`noExpiry`): a session must expire
  - unknown algorithm (`unknownAlgorithm`)
- **B8** Each of those six tokens is refused on the real-time connection.
- **B9** A request with no token gets `GET /me` with `401`.
- **B10** A valid session of an account with no user profile (`tokenOfUserWithoutProfile()`) is refused on the
  real-time connection.
- **B11** A real-time connection with an empty session (`token: ''`) is refused.
- **B12** A connection opened with a session that expires a few seconds later (`shortLivedTokenOf(user, 2)`)
  receives `session_expired` once it expires.
- **B13** That connection is closed by the server after its session expires (wait a few seconds past the expiry).

## Fixture notes
- Base users only; no other fixtures. Use a participant (no staff role), e.g. `participant(1)`.
- Each case states the actor's session explicitly; don't reuse a refused socket.
- B12–B13: give the wait a margin of a few seconds over the token's lifetime; keep the lifetime short (2 s).
