## Vocabulary
- Modify = `PUT /hackathons/{hackathonId}` with the changed fields. Read back with `GET /hackathons/{hackathonId}`.
- Announced = state `OPEN`. The location can be modified while announced (it's not date, type or edition).
- Guest = not logged in; participant = authenticated, no staff role; staff = facilitator, designer, administrator.

## Test cases
Who is rejected
- **B1** A participant modifying the location of an announced on-site hackathon → `403`, and the location is
  unchanged when read back.
- **B2** A participant enrolled in that hackathon, and an evaluator of it, are rejected the same way: `403`,
  location unchanged.
- **B3** A guest modifying it → `401`, location unchanged.

Who may modify
- **B4** A facilitator modifies the location → `2xx`, and the new location is shown when read back.
- **B5** A designer and an administrator can do the same (general.md "Actors").

## Fixture notes
- `anAnnouncedHackathon({ type: 'ON_SITE' })`: on-site, so it has a location. Omit `edition` to get an announced one.
- `participants: [user]` for the enrolled participant, `evaluators: [user]` (or `anEvaluatorOf`) for the evaluator
  (B2). Use different `participant(n)` for B1 and B2.
- Actors: `participant(n)`, `facilitator(n)`, `designer(n)`, `administrator(n)`.
