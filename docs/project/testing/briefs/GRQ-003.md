# GRQ-003 User notifications → `backend/tests/acceptance/emailNotifications.test.js`

> Scope (2026-11-14): sending an email never stops the server, whether the email is delivered or the email service
> is down. Quick registration is only the trigger that makes the system send an email: nothing about registration
> itself is tested here. Registration, UC-035 and the other notifications are tested when Phase 1a reaches them.

## Requirement
- GRQ-003 User notifications (`srs-export.txt` ~line 657): "The system shall be able to send email notifications to
  all types of user, about event announcements and invitations, and SciArt product updates."
- NFRQ-013 Email service integration (~line 3479): "The system shall integrate with an email delivery service to
  send invitations, notifications, and system communications."
- UC-005 postcondition (~line 883): the user is "pre-registered if they were not previously registered". Quick
  registration is that pre-registration, and it sends an email.
- No pending change in `srs-changes.md`.
- The SRS doesn't say what happens when the email service is down. User's decision (D-065, 2026-11-14): the request
  still succeeds, the email is lost (recorded as not delivered), and the server keeps running.
- Why one trigger is enough: every email goes through the same sending path, and the test setup already fails any
  test during which the server would have crashed (`HELPERS.md`, "Work after the response, and server crashes"),
  so later tests of other endpoints that send emails check it too.

## Clarifications
- No clarification file for registration yet.
- `docs/project/clarifications/general.md`: "Actors", "HTTP meaning".

## Vocabulary
- Trigger = quick registration: `POST /register?method=quick` with `{ email }`, as a guest.
- "The server keeps running" = `serverCrashes()` is empty after the request.
- "Email service down" = `failEmailDelivery()`; a send that fails shows in `undeliveredEmails()`, not in
  `sentEmails()`.

## Test cases
- **B1** Email delivered: a guest quick-registers an email → `201`; one email is sent to that address; the server
  keeps running.
- **B2** Email service down: the same request → still `201`; the email to that address is not delivered (and none is
  sent); the server keeps running.

## Fixture notes
- Use a fresh address (e.g. `new.user@example.org`) that no fixture user has.
- Check only the status code, the emails and the crashes: not the response body, nor whether the pre-registration
  was stored.
- Wait with `settle()` before checking emails or crashes.
