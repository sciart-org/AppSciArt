## Vocabulary
- Ongoing hackathon in group work = `anOngoingHackathonAt('GROUP_WORK', …)`. Exploring group = `aGroup(…)`; the
  group's id is its map's id.
- Every event below is answered by the server once handled, refused or not: send it with
  `await socket.timeout(2000).emitWithAck(event, ...args)`. A refusal sends `error_message` (a text) to the sender
  and changes nothing. Changes are not echoed back to the sender.
- A member gets the map by joining the hackathon (`socketAs(member, { hackathon })`): joining puts them in their
  own group's map. A participant placed in a group after joining joins again to get it.
- Staff and evaluators join the hackathon, then `watch_group` with the group's id to follow one map, and
  `stop_watching_group` to stop.
- `get_initial_state`: the sender receives `initial_state`, the map of the group they are in or watch.
- `update_nodes` with the full list of nodes: the others in that map receive `new_nodes` with that list.
  `update_edges` / `new_edges` work the same for edges.
- A node is an object with a text `id`, e.g. `{ id: 'n1', position: { x: 0, y: 0 }, data: { label: 'Idea' } }`. An
  edge is an object with a text `id`, e.g. `{ id: 'e1', source: 'n1', target: 'n2' }`. Compare the lists you sent
  with the ones received; don't check other parts of the messages.
- Stored map: `GET /exploring-groups/{groupId}/conceptual-map` as a facilitator. The map is stored after the last
  socket leaves it; poll for a few seconds until it shows.

## Test cases
Members
- **B1** A member's `update_nodes` reaches another member of the same group as `new_nodes` with the same list.
- **B2** A member's `update_edges` reaches another member as `new_edges` with the same list.
- **B3** After a member's change, another member's `get_initial_state` returns the changed nodes.
- **B4** A participant placed in a group after joining joins again and then receives that group's `new_nodes`.

Other participants
- **B5** A member of another group doesn't receive this group's `new_nodes`.
- **B6** A member of another group's `update_nodes` doesn't reach this group's members.
- **B7** An enrolled participant with no group gets `error_message` for `get_initial_state` and for `update_nodes`.
- **B8** A participant gets `error_message` for `watch_group`, even with their own group's id.

Evaluators
- **B9** An evaluator watching the group receives the members' `new_nodes`.
- **B10** An evaluator's `update_nodes` gets `error_message` and doesn't reach the members.

Staff
- **B11** A facilitator watching the group receives the members' `new_nodes`.
- **B12** A facilitator's `update_nodes` reaches the members as `new_nodes`.
- **B13** `watch_group` with the id of a group of another hackathon gets `error_message`.
- **B14** After `stop_watching_group`, the facilitator no longer receives the group's `new_nodes`.

Stored map
- **B15** After every socket in the group leaves, the stored map has the last nodes a member sent (IRQ-009).
- **B16** An evaluator's refused change is not stored: after everyone leaves, the stored map has the members' last
  nodes.

Bad requests
- **B17** An `update_nodes` that isn't a list, or whose nodes lack an `id`, gets `error_message`, doesn't reach the
  other members, and the server keeps running (`serverCrashes()` is empty).
- **B18** `get_initial_state` and `update_nodes` from a socket that joined no hackathon get `error_message`, and the
  server keeps running.
